Структура очищенной страницы строго: `<header>` → `<main>` → `<footer>`. **Все секции лежат
внутри `<main>`.** Секций-соседей `main` быть не должно.

**Why:** реально выходило `main > section section`, потом main закрывался, и ещё две секции лежали
снаружи. Логика меню видит только секции в контентной области — секция снаружи `main` невидима для
привязки, её якорь никуда не ведёт, и пункты меню теряются. Структурный дефект тихо превращается в
«якоря не присосались», и чинишь потом не то.

**How to apply:** контракт `verify_output_contract` проверяет: ровно один header/main/footer,
лендмарк внутри main = нарушение, main держит >=25% текста. При сборке `main` дожирает соседние
контентные блоки; `repair_landmarks_in_main` вынимает лендмарки, попавшие внутрь. После правки
сборки — проверять, что секций снаружи main ноль. Подробности: docs/CLEANER.md, глава про структуру.

Связано: [[read-specs-before-fixing]], [[extend-dont-narrow-fix]].

## РЕЦИДИВ (2026-07-20) — почему вернулось и как закрыто

Дефект «секция снаружи main» уже чинили в этот же день, и он ВЕРНУЛСЯ. Две причины, обе важные:

1. **Починка была с оговорками.** Дожирание соседей main пропускало блоки по условиям (внутри
   лендмарк, пустой блок). Секция попала под оговорку и осталась снаружи.
2. **Контракт не проверял этот случай.** Он ловил «лендмарк ВНУТРИ main», но не обратное — секцию
   СНАРУЖИ. Поэтому рецидив прошёл молча. Проверка добавлена.

## Грабля bs4, из-за которой проверка сначала не работала

`if tag not in main.descendants` — в BeautifulSoup оператор `in` сравнивает теги **по разметке, а
не по объекту**. Две одинаковые секции считаются одной и той же, и проверка помечала дефект чистым.
Сравнивать надо через `tag.find_parent("main") is None` либо по `id()`. То же самое касается
`list.index(tag)` и любых `tag in collection` — эта грабля есть по всему коду.

**Вывод, применимый ко всему проекту:** починка, у которой есть ветки-исключения, обязана
сопровождаться проверкой в контракте. Иначе исключение однажды сработает, и никто не заметит.
