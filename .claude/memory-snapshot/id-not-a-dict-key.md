`id()` в CPython — это АДРЕС в памяти, и он переиспользуется после сборки мусора. Ключ `id(soup)` в
словаре, который живёт дольше самого объекта, рано или поздно попадёт в чужой документ.

**Как это стоило восьми заходов (2026-07-20).** `classify_headings` кэшировала разбор заголовков в
`_HEADING_CLASS_CACHE[id(soup)]`. Чистильщик разбирает документы пачкой; новый `soup` садится на
адрес освобождённого, сторожевая проверка «столько же заголовков» совпадает — и функция отдаёт теги
ЧУЖОЙ, уже мёртвой страницы. Вызывающий код сверяет их через `id()`, совпадений в живом документе
нет, ни один заголовок не признаётся карточкой. Наружу это выходило как три противоречивых числа
разом: ноль `<h2>`, карта из 11 разделов, меню из одного пункта.

**How to apply:**
1. Кэш на документ — атрибутом НА объекте (`setattr(soup, "_wb_...", value)`). Умирает вместе с ним,
   перепутать документы нечем.
2. `id()` годится только внутри одного выражения/прохода, пока объекты заведомо живы (например
   множество `{id(h) for h in sections}` для сравнения по тождеству прямо здесь же).
3. Симптом подмены документа: функция отработала «успешно», но ни одно `id`-сравнение у вызывающего
   не совпало.
