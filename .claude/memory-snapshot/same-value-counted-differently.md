Самый частый источник багов в этом проекте: **две части кода считают одно и то же по-разному**,
каждая по отдельности работает правильно, а вместе дают расхождение.

**Случаи за одну сессию (2026-07-20):**
- «какой элемент хедер» решали ЧЕТЫРЕ места с разными признаками (класс / класс+id / первый `<nav>`
  в документе / требуется href). Пара CTA-кнопок дважды пролезала в хедер: закрывал один вход —
  заходила через другой. Свёл в одну функцию `can_be_header`;
- «живые ссылки меню» считались то по верхнему уровню, то по всему контейнеру — из-за этого чистка
  мёртвых пунктов отключалась и оставляла 57 мёртвых надписей;
- «сколько разделов на странице» считалось до и после фильтра виджетов: 24 против 2, и запасное
  правило не включалось;
- ДВА агента писали в одно поле подписи секции: один давал `about`, другой уже занял поле значением
  `Rightcomtext`, и второй побеждал.

**How to apply:**
1. Добавляя проход, ПЕРВЫМ делом посмотреть, кто ещё вычисляет ту же величину и по каким правилам.
2. Если правило повторяется в двух местах — вынести в одну функцию, а не копировать.
3. Порядок вызовов важен не меньше самой логики: поздний проход способен отменить решение раннего
   (корректор ролей затирал правильно собранный `<main>`).
4. Симптом этого класса: три числа противоречат друг другу (например «11 секций в карте», «ноль
   h2» и «1 пункт меню» одновременно).
